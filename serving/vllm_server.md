# vLLM Server Runtime Notes

InferLab treats vLLM as a serving backend to measure, not only a command to
copy. The important runtime path is request admission, continuous batching,
PagedAttention-backed KV cache use, GPU execution, and OpenAI-compatible
response timing.

## Container Entry

The GPU compose profile uses `docker/Dockerfile.vllm` and starts:

```bash
python3 -m vllm.entrypoints.openai.api_server \
  --model "$INFERLAB_MODEL" \
  --host "$INFERLAB_HOST" \
  --port "$INFERLAB_PORT" \
  --dtype "$INFERLAB_DTYPE" \
  --max-model-len "$INFERLAB_MAX_MODEL_LEN"
```

Tune `INFERLAB_MAX_MODEL_LEN`, model path, dtype, and GPU count through
`deploy/inferlab.runtime.env` generated by `scripts/plan_runtime_deploy.py`.

## Metrics To Capture

- TTFT, TPOT, request throughput, completion-token throughput, P50/P90/P99
  latency, failed request count.
- GPU memory at model load, peak active batch, KV cache pressure, and prompt vs
  decode token mix.
- vLLM scheduler and worker logs around queueing, prefill, decode, and stream
  response chunks.

## Source Reading Targets

- scheduler request admission and waiting/running queues
- block manager and KV cache allocation
- attention backend dispatch
- OpenAI-compatible server request path
- metrics export path when Prometheus is enabled
