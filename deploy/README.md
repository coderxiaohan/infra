# InferLab Runtime Deployment

This directory contains Docker Compose entrypoints for later CPU/GPU machines.
The current development server does not need Docker or NVIDIA Container Toolkit
for these files to be useful.

## Files

- `docker-compose.inferlab.yml`: development container and GPU vLLM service
  profile.
- `docker-compose.observability.yml`: node_exporter textfile collector,
  Prometheus, and Grafana.
- `inferlab.runtime.env`: generated by `scripts/plan_runtime_deploy.py` and
  intentionally ignored by Git. Sensitive values are omitted by default; set
  `GRAFANA_ADMIN_PASSWORD` in a private env file or shell on the target machine.

## Generate A Plan

```bash
python3 scripts/plan_runtime_deploy.py \
  --profile full \
  --model-root /models \
  --model /models/model \
  --model-name model \
  --output reports/runtime_deploy_plan.md \
  --json-output results/raw/runtime_deploy_plan.json \
  --env-output deploy/inferlab.runtime.env
```

Add `--write-sensitive-env` only on a private target machine when you explicitly
want the generated env file to contain sensitive values.

The planner records whether Docker, `nvidia-smi`, compose files, model roots,
and textfile metric directories are present. It writes commands but does not
run them.

## Suggested Order On A GPU Machine

1. Build the dev image and confirm the repository mounts correctly.
2. Build the vLLM image with the CUDA/Python package versions needed by that
   machine.
3. Start `vllm-server` with a legal model mounted read-only.
4. Run `scripts/run_vllm_benchmark.py` against the OpenAI-compatible endpoint.
5. Export `results/tables/inferlab_metrics.prom`.
6. Start the observability compose stack and import the Grafana dashboard.
